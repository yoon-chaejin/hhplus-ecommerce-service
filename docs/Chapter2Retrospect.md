# 챕터 2 회고

## 4L
- 좋았던 것 (Liked)
  - 코치님들과 동료들의 의견을 다양하게 들어보고, 그 중에서 내가 실행 가능하다고 생각하는 MVP를 수립해서 진행한 것
  - 허재 코치님의 "나는 코드를 이렇게 짠다" 순서에 맞춰서 개발해본 것
  - 27팀 팀원들과 비공식 32팀 (헤네시스 일진) 팀원들, 그리고 서각코(서울서부 모각코)와 같이 서로 밀어주고 당겨주며 함께 한 것
- 배운 것 (Learned)
  - 설계부터 개발, 테스트까지 하나의 흐름으로 개발하는 방법
  - 테스트 코드를 작성할 때 고려해야 하는 것들
  - Spring 과 JPA 라는 기술이 왜, 어떤 기능을 제공하는지에 대해서
- 부족했던 것 (Lacked)
  - 시간. 특히 몰입해서 개발하는 시간. 프레임워크에서 제공하는 어떤 기능을 사용할 때, 프레임워크는 왜 그 기능을 지원하는지, 어떻게 동작하는지에 대해서 좀 더 알아보지 못했다.
  - 뾰족하게 생각하는 것. 1주차 설계 때도 주말에 느슨하게 했던 분석이 결국 목요일까지 점차 뾰쪽해졌었고, 1주차의 느슨한 설계가 2주차에 구현하면서 뾰족해졌다.
- 바라는 것 (LongedFor)
  - 테스트를 위한 데이터를 보다 유연하게, 독립적으로 관리할 수 있도록 하는 것
  - SQL에 대한 의존을 보다 줄여보는 것
  - 프레임워크에서 제공하는 어떤 기능을 사용할 때, 프레임워크는 왜 그 기능을 지원하는지, 어떻게 동작하는지에 대해서 좀 더 알아보는 것

## KPT
- Keep
  - 뾰족하게 분석하기. 테스트 케이스 이름을 사전에 고민해보기
  - 매일 꾸준하게 공부하기. 다른 사람의 코드, 이야기를 듣는 것도 충분히 도움이 된다.
- Problem
  - 테스트 코드에 필요한 데이터를 세팅하는 부분이 독립적으로 관리되고 있지 않다.
  - 개선사항들은 점차 쌓여가지만, 당장 해야하는 과제를 수행할 시간도 부족하다.
- Try
  - 테스트 코드 및 테스트 데이터 격리시키는 작업 진행하기. 최대한 설 연휴를 활용하자.
  - 개선사항들을 목록으로 정리하고, 우선순위와 작업규모를 고려해 점진적으로 도입하기.
